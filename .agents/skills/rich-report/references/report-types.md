# Report types and visuals

Read this reference when deciding what readers should see first, what evidence they need, and how they should explore it. Choose the type that matches their main question. Use its opening and borrow supporting sections where they help answer that question.

| Report type | Lead with | What to show and verify | Useful visual or interaction |
| --- | --- | --- | --- |
| Executive brief | The outcome, why it matters, and the decision or action needed. | Explain impact, confidence, and the time window. Make the evidence for each takeaway easy to find. | A small set of labeled metrics with context, or a one-screen decision summary. |
| Status or progress report | What's on track, what's at risk, and the help needed. | Include the date, completed and upcoming milestones, blockers, owners, and recovery dates. Explain what each status means. | A milestone timeline with a switch between planned and current dates. |
| Plan or roadmap | The goal, next milestone, and key decision points. | Show timing, sequencing, dependencies, uncertainty, and ownership. Distinguish committed work from proposals. | A timeline or dependency diagram with expandable work details. |
| Decision memo or options comparison | The decision, recommendation if requested, and why it matters now. | Compare viable options using the same criteria. State assumptions, reversibility, cost, and what would change the choice. | A comparison matrix with expandable evidence, or scenario controls for inputs that change the result. |
| Research or literature review | The question and the strongest defensible conclusion. | Cover scope, source selection, agreement and disagreement, evidence strength, and knowledge gaps. Separate inference from reported findings. | An evidence map with filtering by finding, source type, or strength. |
| Concept explainer | The simplest accurate explanation and one concrete example. | Move from an everyday case to the model, then cover limits and edge cases. Identify what each illustration abstracts away. | An annotated diagram, progressive reveal, or a small what-if demonstration. |
| Tutorial or learning guide | What the reader will be able to do and what they need to start. | Order steps from a worked example to practice. Give expected results and explain common errors. | A step-through example, self-check, or expandable worked solution. |
| Procedure, runbook, or troubleshooting guide | When to use it and the first safe action. | Include prerequisites, branching conditions, expected signals, verification, and recovery. Put warnings at the affected step. | A decision flowchart with a readable list of the same branches. |
| System or architecture walkthrough | What the system does, its boundary, and a typical journey through it. | Follow actors, inputs, state, outputs, and failure paths. Mark observed behavior and proposed changes clearly. | A layered system map and a step-through request or event sequence. |
| Metrics snapshot or dashboard | The time period, headline change, and why it deserves attention. | Define units, baselines, filters, denominators, freshness and missing data. Keep comparisons on equivalent scales. | A trend with breakdown controls and a data table. |
| Analytical report or data story | The answer the data supports and its size or practical impact. | Show the population, methods, sample, uncertainty, and plausible alternative explanations. Distinguish correlation from causal evidence. | A sequence of annotated charts, a distribution view, or a drill-down by segment. |
| Financial report or forecast | The result or range, key drivers, and major exposures. | Separate actuals, targets, and projections. State currency, reporting period, assumptions, and sensitivity. | An actual-versus-plan bridge, or a scenario comparison with resettable inputs and visible assumptions. |
| Market, competitor, or landscape review | The important pattern and its implications for the reader. | Define the market, period, selection criteria, source quality, and gaps. Use fair comparison criteria and label estimated figures. | A positioning map, segmented comparison, or market-sizing breakdown. |
| Customer feedback, survey, or user research | The strongest user need and who reported it. | Report sample, collection method, segmentation, limitations, and representative evidence. Anonymize participant details as required. | A theme breakdown, journey map, or toggle between segments and quotes. |
| Incident review or postmortem | What happened, who or what was affected, and current status. | Record confirmed timeline, timezone, contributing factors, detection and recovery, and actions with owners. Label open hypotheses. | A timeline grouped by detection, response, recovery, and follow-up. |
| Audit, readiness, or risk assessment | The overall result and the most consequential findings. | Show scope, criteria, evidence, exceptions, impact, confidence, and remediation responsibility. Define severity and likelihood labels. | A findings table with filters and details, or a labeled risk matrix. |
| Test, benchmark, or evaluation report | The verdict, comparison baseline, and most relevant differences. | Include versions, environment, workload, measurement method, criteria, repeat count, and variability. Name gaps and any limits on reproducibility. | A side-by-side result with distributions, thresholds, or scenario drill-down. |
| Retrospective or lessons learned | Which practices to keep and what needs to change. | Ground lessons in outcomes. Give each proposed action an owner, a follow-up date, and a success signal when those are known. | A timeline tied to decisions and actions, or an impact-and-effort comparison. |
| Change summary or release report | What changed for the audience and what they need to do. | Group by affected audience or workflow. Include version, date, compatibility, required migration steps, and where to get help. | A before-and-after walkthrough or a filterable list of affected areas. |
| Case study or portfolio report | The problem, result, and why the case is relevant. | Show initial conditions, work done, measured outcomes, time horizon, and any limits on attribution. | Before-and-after evidence, an annotated walkthrough, or an interactive sequence of decisions. |
| Historical or geographic report | The defining change over time or the meaningful difference across places. | Make time and location boundaries explicit. Identify source gaps, boundary changes, and whether counts need to be normalized. | An event timeline or labeled map with an equivalent table. |

## Match the visual to the question

- **How did it change?** Use a line chart for a continuous trend and a timeline for discrete events. Show gaps as gaps and label meaningful changes in measurement.
- **Which is bigger or different?** Use aligned bars, dots, or a table with units. Start length-encoded bars at zero. Show the base count when a rate or percentage needs context.
- **How are values spread?** Use a distribution plot or summary with counts and variation. Annotate outliers when the evidence supports an explanation.
- **How does it work?** Use a flowchart for branches, a sequence diagram for exchanges, or a layered map for relationships. Label arrows with what moves or changes.
- **What if an assumption changes?** Add controls only for meaningful inputs. Show the current assumptions next to the result and label hypothetical outcomes. Keep the initial result understandable before anyone uses a control.
- **Where did it happen?** Use a map when location explains the pattern. Include labels and an equivalent table so readers can still compare values by place.

Put the takeaway and source beside the visual. Keep important information available as text or a table as well, even if a reader never uses the controls.
